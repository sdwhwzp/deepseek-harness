# 同步个人 fork

[English](synchronizing-personal-forks.md) | 中文

这些规则适用于本 Harness fork 及其已引入的 dsh 插件 fork。同步前，记录每个源仓库与分支、自有 fork 的推送地址、当前分支和远端提交。

1. 首先 fetch 源仓库与自有远端，保留未提交工作。将获取的源代码合并到当前工作分支；旧 `dev` 或默认分支不能替代实际部署分支。
2. 解决冲突时优先采用源实现。以最小本地修改适配当前 Harness 与用户要求，保留必要的账号隔离与持久化数据兼容性。不得通过 reset 或批量冲突覆盖丢弃未合并工作。
3. 按[推送前检查](../../.agents/skills/dsh-pre-push-checks/SKILL.md)完成适配和相关检查后再推送。检查失败时，同步仍未完成。
4. 枚举每个同步仓库的全部本地分支，将所有未发布分支和提交上传到自有 fork。确认每个远端分支与本地提交一致，不能只推送当前分支。保留分支历史和仅存在于远端的分支；禁止 `--mirror` 和直接使用 `--force`。
5. 全部推送后再次 fetch，对照最新源提交检查当前分支及剩余源差异。若仍有新源提交，继续合并、适配、检查和推送。报告分支哈希、检查结果与有意保留的适配差异；只有不存在遗漏源提交和未发布本地分支时，才能宣告完成。
