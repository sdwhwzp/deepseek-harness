# Agent Note: 纯文本路由下的工具结果图片显示

Status: implemented

[English](2026-08-26-tool-result-image-display.md) | 中文

## 问题

`read_image` 会产生持久 `ImageBlock`，但未声明图片输入的模型路由会阻止工具读取文件。Web 对话只渲染用户与 assistant 消息中的图片块，因此其他成功工具结果只暴露路径或持久引用，不显示像素。模型输入模态与对话展示属于不同职责。

## 决定

带图片的工具结果是持久对话内容，不依赖当前模型的输入模态。

- `read_image` 仍依赖持久附件服务、受支持的 PNG/JPEG/WebP/GIF 来源和部署图片上限。在支持图片、纯文本、能力未知和无法解析的模型路由下，它都会保存图片并追加标准的文本与图片工具结果。无扩展名路径继续通过内容签名识别格式。
- `ToolCallTree` 从每个已结算 root 与嵌套工具结果中提取标准图片块，直接渲染在所属工具行下方。`read_image` 使用既有 read 行展示。
- 工具结果图片使用 conversation 所属的历史图片 renderer，并采用 `start` 对齐。附件展示插件继续负责会话授权加载、按会话共享的 object URL 缓存、缩略图尺寸、重试行为和原图灯箱。
- 模型请求投影继续对模态拥有最终决定权。支持图片的路由接收请求像素；确切的纯文本路由接收稳定的附件占位符，事件日志与 Web 预览仍保留图片引用。

因此，在默认 Web 组合中，即使活动模型是纯文本模型，`read_image` 读取生成图片或文件系统图片后也会在对话内显示。任何其他追加标准图片块的工具，其 root 与嵌套调用都会得到相同展示。

## 考虑过的替代方案

**保留严格执行门禁。** 这可以避免产生模型无法检查的图片结果，却也会压制用户可以检查的有效持久产物。请求投影已经阻止不受支持的像素进入纯文本模型。

**只返回文件系统路径，并要求用户在对话外打开。** 宿主路径无法跨远端移植，不具备会话授权，也不会显示在恢复后的 Web 历史记录中，同时不能提供所需的内嵌交互。

**让 Web 客户端直接加载本地文件系统路径。** 浏览器无法安全且一致地读取任意宿主路径，这类 URL 还会绕过持久附件的授权与完整性检查。渲染已记录的附件引用可以复用既有授权路径。

**添加 `read_image` 专用 UI 组件。** 图片块属于标准工具结果内容词汇，可来自 root 调用、Code Dispatch 子调用、MCP 工具或后续图片提供方。按内容类型渲染能使展示与工具名称解耦。

## 后果

- 纯文本模型无法检查像素，只能看到确定性占位符，但用户可以在同一对话中预览和打开持久图片。
- 重复读取图片会增加持久历史，并增加后续支持图片路由的请求成本；内容寻址去重存储字节，不去重消息中的出现次数。
- 未组合可选附件展示插件时，持久结果仍存在，但不渲染图片画廊。默认 Web bundle 包含该插件。
- root 与嵌套工具结果复用用户和 assistant 历史记录所用的授权 loader、按会话缓存与灯箱，因此客户端渲染接口中不出现文件系统 URL 或 base64 载荷。
